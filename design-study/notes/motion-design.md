# 动效设计（Motion Design）学习笔记

> 学习日期：2026-10-17（第六轮）
> 学习背景：网站案例"旋转"被潘熠两次批评"非常的不协调且生硬"（10-16、10-17），26 秒自动转圈被删、改成鼠标跟随倾斜。本轮把"动效"当作独立技能补上——之前 21 份笔记里没有动效，这是真正的缺口。
> 资料来源：wpdean《CSS Card Hover Effects》《CSS Flip Cards》参数实测汇总（2026-10）、Material Design / Apple HIG 动效时长与缓动规范、WCAG 2.2.2（Pause, Stop, Hide）、GitLab UX 动效指南；以下均为转述与判断，非原文摘抄。

---

## 一、时长：200–500ms 是甜点区

| 时长 | 人的感受 |
|---|---|
| < 100ms | 等于没有，感知不到 |
| 200–300ms | 移动端甜点，利落 |
| 200–500ms | 桌面端甜点，通用安全区 |
| > 1s | 感觉"卡"、"慢"，用户开始烦躁 |

**规则**：
1. **进入慢、离开快**：元素进入视线/展开用 200–400ms；离开/收起用 100–200ms。离开的东西不值得观众等它。
2. 距离越长，时长越长——但先问"能不能不动这么远"。
3. 全屏级大动效先怀疑：能不能拆成小动效？大动效超过 400ms 就显得拖沓。
4. 站点的 reveal 入场 `.85s` 偏长（在甜点区上限之外），但它是"首次加载的编排"而非交互反馈，可以接受；**交互反馈（悬停、点击）必须 ≤500ms**。

**我的判断**：时长是动效的"音量旋钮"。之前网站的问题一部分就是"26 秒自动转圈"——时长失控。以后定动效先定**时长预算**，再谈花样。

## 二、缓动：曲线是"语气"

直接可用的曲线（抄作业级别）：

| 曲线 cubic-bezier | 用途 |
|---|---|
| `(0.4, 0, 0.2, 1)` | 通用默认，Material 标准缓动 |
| `(0.16, 1, 0.3, 1)` | 进入/展开，更柔和的减速（站点在用，选得对） |
| `(0.0, 0, 0.2, 1)` | 元素进入屏幕，减速入场 |
| `(0.4, 0, 1, 1)` | 元素离开屏幕，加速离场 |
| `(0.34, 1.56, 0.64, 1)` | 轻微弹簧，只给高光时刻（成功态、彩蛋） |

**规则**：
1. **位移永远不用 linear**：匀速运动在人眼里是"机械的"、廉价的。linear 只配给透明度/颜色过渡。
2. 一个产品只用一套缓动家族（进入/离开/默认各一条），全站统一——动效的"口音"要一致。
3. 弹簧（spring/overshoot）是辣椒面：一年用几次是惊喜，天天用是"不稳定"。
4. 手势驱动的动效（如拖拽）才值得上物理弹簧；普通 CSS 过渡用 cubic-bezier 就够了。

## 三、3D 倾斜卡片：参数有标准答案

综合 2026-10 实测的多份教程，参数收敛得很集中：

| 参数 | 安全区 | 说明 |
|---|---|---|
| perspective | 卡片宽度的 **3–4 倍**（常用 800–1200px） | 越小越夸张，越大越克制 |
| 最大倾斜角 | **4–8°**（克制高级）；15° 是上限 | 超过 10° 开始有"玩具感" |
| 跟随方式 | JS 读鼠标位置 + **rAF 插值平滑**（lerp 0.12–0.2） | CSS transition 直接跟鼠标会抖 |
| 过渡 | 进入/回正 0.15–0.3s ease-out | 回正要比跟随更快更脆 |
| 背面 | `backface-visibility: hidden` | 有翻面才需要；纯倾斜不需要翻面 |

**规则**：
1. **鼠标跟随必须用 rAF 插值**，不能直接把鼠标坐标写进 transform——直接写会产生高频抖动，这就是"生硬"的技术根源。`current += (target - current) * 0.16` 这一行是顺滑的全部秘密。
2. **离开必须自动回正**（mouseleave 把目标角度清零），否则卡片会"僵"在一个歪角度。
3. 倾斜是桌面专属：`pointer: fine` 检测，触屏/手机直接关掉——手机上没有悬停，倾斜代码跑了也白跑。
4. 必须尊重 `prefers-reduced-motion`：晕动症用户看到 3D 晃动会真的难受。
5. **只动 transform 和 opacity**：这两个走 GPU 合成器，不触发布局重排。动 width/height/top 是性能自杀。

**我的判断**：±2–2.5° 是"感知阈值之下"——很多人根本看不出在动；4–8° 是"能感到高级"的区间。克制不等于没有，**动效的及格线是"用户能感知到，但说不出哪里动了"**。

## 四、自动播放：能删就删

**WCAG 2.2.2（Pause, Stop, Hide）**：自动开始、持续超过 5 秒的动态内容，必须提供暂停/停止/隐藏机制。自动转圈的案例卡片如果没有暂停按钮，**本身就是无障碍不合规**。

**规则**：
1. 自动旋转/自动播放的默认答案是**删掉**，改成用户驱动（悬停、点击、滚动触发）。
2. 非删不可的（如 hero 背景氛围动效）：幅度要小、速度要慢、必须响应 reduced-motion。
3. "26 秒自动转圈"被删掉，从规范角度看不是"妥协"，是"本来就该这么做"。

## 五、动效也要分级（一级/二级/三级）

和按钮的三级体系同一个逻辑：

| 级别 | 场景 | 幅度 |
|---|---|---|
| 一级 | hero 入场、页面转场 | 可以华丽，但一生一次 |
| 二级 | 卡片悬停、展开收起 | 克制，transform + 阴影 |
| 三级 | 按钮按压、链接悬停 | 极简，2px 位移 / 透明度 |

**规则**：一次只动一个属性族。卡片悬停 = 倾斜 + 上浮 + 阴影加深，已经是上限；再加旋转+缩放+变色就是"土"的开始。

---

## 六、交错（Stagger）与视差

1. **列表入场交错 40–90ms 递增**：站点用的 70ms 落在安全区。超过 120ms 会感觉"排队"。
2. **Hero 视差位移 10–20px**：站点 hero 用 14px/9px，克制正确。视差超过 30px 容易晕。
3. 交错只用于"首次进入视口"，滚动回来不重播（否则每次滚动都在跳舞）。

---

## 七、验收铁律：录屏慢放

1. 动效不能只看代码"觉得对了"——**必须录屏，用 0.5 倍速看一遍**：抖动、跳帧、回正不彻底在慢放下无所遁形。
2. 验收三问：① 时长在 200–500ms 内吗？② 离开回正了吗？③ 手机上关掉了吗？
3. 让用户"上手划一下"是验收的一部分，但**要告诉用户在什么设备上测**——桌面动效让用户在手机上测，等于没测。

---

## 八、一句话总结

> **动效的高级感 = 克制的幅度 + 正确的缓动 + 用户驱动。**
> 幅度取感知阈值上一点（4–8°），缓动用 ease-out 家族，自动的一律改手动。
> 报"改完了"之前，先录屏慢放自己看一遍。
