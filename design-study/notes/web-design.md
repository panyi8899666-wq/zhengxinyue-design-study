# 网页设计学习笔记

> 学习人：Muse（潘熠的 AI 设计助手）
> 日期：2026-10-17
> 背景：第五轮设计深造（8 大领域之网页设计）。锚点：潘熠个人作品集网站——深色高级风（墨黑 #0D0D0F / 米白 #ECEAE4 / 香槟金 #C6A15B），中文为主、英文点缀，移动端 390px 适配。
> 资料来源：W3C 中文排版需求、Material Design 深色指南、Apple HIG、Core Web Vitals 文档、Baymard 研究所、Medium 设计专栏。以下均为转述与判断，非原文摘抄。

---

## 一、网页排版

### 1.1 屏幕字体：系统字体栈 vs Web Font

**原则**：中文字体文件动辄几 MB，Web Font（在线加载中文字体）是首屏速度杀手。中文网站的标准做法是**系统字体栈**——按优先级列出用户设备上已有的字体，浏览器从前到后取第一个可用的。

**潘熠网站的字体栈**（已定，2026-10-15）：
```
"Microsoft YaHei", "PingFang SC", "Hiragino Sans GB", sans-serif
```
微软雅黑优先（Windows 覆盖最广），苹方/冬青黑回退（苹果设备）。英文更小、更轻、更低对比，只做装饰点缀。

**我的判断**：
- ✅ 正例：系统字体栈 = 零加载成本 + 各平台都有"本地优化过"的字形。苹方在 iPhone 上的渲染是苹果调过的，比任何 Web Font 都舒服。
- ❌ 反例：为了"个性"加载 8MB 的中文 Web Font，首屏白屏 3 秒——个性是有了，客户走了。
- **落点**：除非品牌有定制字体且已做子集化（只打包用到的字），否则中文网站永远用系统栈。英文装饰字可以用 Web Font（英文文件小），但潘熠的英文只是点缀，系统英文同样够用。

### 1.2 行长：45~75 字符

**原则**（Baymard 研究所 + 多份排版指南）：正文行长 45~75 字符（英文）最易读。太宽眼睛找不到下一行行首，太窄换行频繁打断思路。中文按"字"算，舒适区间约 24~40 字/行（汉字信息密度高）。

**落点**：
- ✅ 潘熠网站的服务介绍、流程说明这类段落，桌面端用 `max-width: 65ch` 锁住行长，移动端自然收窄。
- ❌ 反例：全宽 1440px 一行排 60 个汉字——没人能一口气读完，读者会直接跳过。
- **动手检查**：桌面端数一行字数，超过 40 个汉字就收窄容器。

### 1.3 移动端字号

**原则**：移动端正文字号不小于 16px（iOS 小于 16px 的输入框聚焦时会自动放大页面，造成布局跳动）。标题用 fluid type（`clamp()`）让字号在断点之间平滑缩放，而不是跳变。

**落点**：
- 潘熠网站已验证 390px 无横向溢出。下一步：检查所有正文 ≥16px，按钮触控高度 ≥44px（已定规范）。
- 中文在手机上比英文更需要字号——同样 16px，汉字的笔画密度高，小一号就糊。移动端中文正文建议 16~17px 起步。

### 1.4 深色模式配色

**原则**（Material Design + Apple HIG 共识）：
1. **不用纯黑纯白**：纯黑 #000000 + 纯白 #FFFFFF 对比度 21:1，在 OLED 上会产生光晕（halation），白字发光糊进黑底。推荐深灰底 + 米白字。
2. **点缀色降饱和 10~20%**：高饱和色在深色底上会"发光"，刺眼。用 70~80% 饱和度的版本。
3. **用深浅分层代替阴影**：深色模式里阴影看不见，用"越往上越亮"的 surface 层级表达 elevation。

**落点**——潘熠网站的三色天然符合规范：
| 角色 | 色值 | 规范对照 |
|---|---|---|
| 背景 | 墨黑 #0D0D0F | 非纯黑 ✅（避免光晕） |
| 正文 | 米白 #ECEAE4 | 非纯白 ✅（避免眩光） |
| 点缀 | 香槟金 #C6A15B | 低饱和金属色 ✅（天然降饱和，不过亮） |

**我的判断**：这套配色是"蒙对了规范"——潘熠凭审美选的，恰好每条都踩在深色指南的推荐上。以后给客户做深色网站，直接复用这个逻辑：深灰底 + 米白字 + 低饱和点缀色。

- ❌ 反例：纯黑底 + 纯白字 + 荧光绿点缀——对比度爆表但眼睛 10 秒就累，荧光色在深色底上像灯管。
- **动手检查**：把页面截图转黑白，文字和背景还能分清层级，对比就够了；再看点缀色在深色底上是否"跳"得刺眼。

## 二、布局

### 2.1 12 栅格

**原则**：12 栏是最通用的网格（能被 2/3/4/6 整除，组合灵活）。桌面端内容区一般 max-width 1200~1280px，gutter 24px。**先定断点，再定栏数**——移动端不是"压缩桌面版"，是重新排。

**落点**：
- 潘熠网站案例区：桌面端"1 大 + 3 小"直角网格，移动端改上下堆叠——这就是"断点处重新排"，不是等比缩小。
- 内容页规则（已定）：除首页外一律左文右图，移动端上下堆叠。左文右图在 12 栅格里就是 7:5 分栏。

### 2.2 断点：390 / 768 / 1024 / 1440

**原则**：断点应该按"内容开始难受"的宽度定，而不是按设备型号。但实践中四个锚点够用：
- 390px：手机（iPhone 14/15 标准宽）
- 768px：平板竖屏
- 1024px：小笔记本/平板横屏
- 1440px：桌面主流

**落点**：
- 潘熠网站已在 390px 验证无溢出。建议补 768px 检查：平板竖屏时案例网格是 2 列还是 1 列？导航是汉堡菜单还是展开？
- **动手检查**：Chrome DevTools 逐个断点过一遍，只看三件事——有没有横向滚动条、文字有没有被截断、按钮能不能点到。

### 2.3 首屏设计

**原则**：首屏（above the fold）要在 3 秒内回答三个问题：你是谁、你卖什么、我下一步点哪。首屏不是"把所有东西堆上去"，是"只放让你往下滚的理由"。

**落点**：
- 潘熠网站首屏：居中标题 + 暗粒 ∪ 形拱门 + 英文线 + "立即开始设计"按钮——身份（正鑫越）+ 卖点（设计执行力）+ CTA，一屏三问全答了。
- ❌ 反例：首屏放 2000 字公司简介 + 8 个按钮——用户一个都不点，直接关掉。
- 价格不放首页首屏（已定规范）——首屏卖"信任"，不卖"报价"。

### 2.4 F 形阅读在网页上

**原则**（NN/g 眼动研究）：用户先横扫顶部（导航/标题），再扫第二行，最后沿左侧垂直扫——形成 F 形。所以：重要信息放左上，标题用"关键词前置"，左侧导航/目录是天然的视觉锚点。

**落点**：
- 案例列表页：左侧放筛选/分类（已定的 5 个案例筛选图标按钮），右侧是案例流——符合 F 形的左锚点。
- 案例详情：关键信息（客户类型、交付物）放在左上，别藏在第三屏。
- ❌ 反例：把"立即咨询"按钮放在右下角小字——F 形视线的盲区，等于没放。

## 三、交互

### 3.1 微交互：hover / 按压反馈

**原则**（Dan Saffer："微交互是克制的艺术"）：每个动效只干一件事——告诉用户"我收到了"。动画时长 200~500ms 最佳：短于 100ms 感觉不到，长于 500ms 感觉慢。

**落点**——潘熠网站的 3D 黏土胶囊按钮规范（已定）：
- hover：轻微浮起 + 阴影加深（"我是可点的"）
- 按压：下沉 + 内阴影（"我收到了"）
- 英文标签：与中文等宽、中英文整体居中（已定规范）

**我的判断**：按钮是全站最高频的交互，它的反馈就是品牌的"握手"。黏土质感 + 按压回弹，握手是有温度的。
- ❌ 反例：按钮 hover 时整页跳动、颜色乱闪——微交互变成了"微惊吓"。
- **动手检查**：每个可点元素问自己——hover 时用户知道可点吗？点下去用户知道生效了吗？两个都 yes 才算完。

### 3.2 滚动叙事

**原则**：滚动是最自然的翻页。好的滚动叙事是"一滚一景"：每滚一屏，讲清楚一件事。用视差、渐入、数字滚动营造节奏，但**内容先行**——没有内容的动效是杂技。

**落点**：
- 潘熠网站已有：交错视差 hero、双 marquee、滚动驱动的流程时间线、数字 count-up。
- ⚠️ 风险：动效多了会抢戏。检验标准——关掉所有动效，页面信息还完整吗？如果完整，动效是加分；如果不完整，动效在替内容打工，要砍。
- 移动端：滚动叙事要降级（触摸滚动快，复杂动效跟不上还掉帧）。已定规范：移动端静态或极轻浮动。

### 3.3 加载状态

**原则**：用户能忍受等待，不能忍受"不知道在等"。骨架屏 > 转圈 > 白屏。首屏品牌 preloader 已被证明是坑（潘熠网站曾经的 preloader 卡死 block 页面，已移除）。

**落点**：
- 教训已吃过：branded preloader 直接删掉，不要"优雅的等待"，要"没有等待"。
- 图片用渐进式加载：先模糊占位 → 清晰。案例图多，这是体验关键。

### 3.4 动效的克制：什么时候动，什么时候静

**原则**：
- **动**：反馈用户操作（按压）、引导视线（滚动渐入）、解释状态变化（展开/收起）。
- **静**：阅读区（文章、案例正文）、高频操作区（导航）、用户正在输入时。
- 尊重 `prefers-reduced-motion`：系统开了"减少动态效果"，网站必须跟从——这是无障碍，不是可选项。

**落点**：
- 潘熠网站已定：不恢复自定义鼠标（动得没意义）、案例卡片首页纯图片（静，让作品自己说话）、hover 才变清晰（动，只在用户主动探索时）。
- **一句话**：动效是标点符号，不是正文。满屏感叹号等于没有重点。

## 四、作品集网站专项

### 4.1 案例展示最佳实践

**原则**（综合 Muzli 2026 + 多份作品集指南）：
1. **大图优先**：案例首图要大、要清晰，这是 80% 的第一印象。
2. **过程 > 结果**：只放成品图的是作品集，放"为什么这样做"的是案例研究。客户买的是你的脑子，不是你的图。
3. **标注诚实**：概念/真实客户/个人作品必须分别标注（潘熠已定规范）——诚实是获客资产，虚假是定时炸弹。
4. **不要 show 数量**：不说"20 个案例"（已定规范）——用"多"但不说"多少"，数量是会被拿去比价的。

**落点**：
- 潘熠网站现状：首页案例卡纯图片 + 毛玻璃 hover 变清晰；详情页桌面 hover 聚光灯 + 跟随卡片、移动端药丸 tab 同步规格；真实/概念分别标注。骨架是对的。
- 下一步可加强：每个案例加 2~4 句"设计说明"（为什么这样做、解决了什么问题）——从作品集升级到案例研究。

### 4.2 CTA 设计

**原则**：全站只推一个主 CTA，其他都是配角。主 CTA 文案用动词 + 好处，不要用"提交""点击这里"。

**落点**：
- 潘熠网站主 CTA："立即开始设计"（已定）——动词 + 好处，一键微信风聊天窗口，打开即主动问候。这是全站唯一的主 CTA。
- 定价页 CTA 是"订阅后得到什么"（已定规范：包月后客户得到什么，不是分类报价）——CTA 永远回答"对我有什么好处"。

### 4.3 联系方式呈现

**原则**：联系方式越少越可信。放 2 个邮箱 + 1 个动作（开始设计），比放电话微信 QQ 微博抖音一堆更让人想联系。选择困难 = 不联系。

**落点**（已定规范）：
- 公开版只显示两个邮箱（联系方式已脱敏）
- 隐藏电话、微信二维码、支付二维码——公开渠道不暴露，私聊时再给。这是"门槛设计"：先聊，再加微信。
- ❌ 反例：联系区堆满 6 种联系方式 + 3 个二维码——客户不知道先用哪个，最后哪个都不用。

### 4.4 移动端适配

**原则**：移动端不是桌面端的缩小版，是"拇指操作系统"。检查清单：
- 无横向溢出（390px）
- 触控目标 ≥44px
- 字号 ≥16px
- 导航收进汉堡菜单
- 表格/宽表改卡片式堆叠
- hover 交互要有 touch 等价（hover 变清晰 → 触摸也变清晰）

**落点**：潘熠网站已验证 390px 无溢出、0 破图。案例详情移动端是全屏滚动式（6 个视图纵向贯通）——这是对的，手机用户不点 tab，手机用户只会往下划。

## 五、性能与体验

### 5.1 图片优化：WebP + 懒加载

**原则**：
- WebP 比 JPEG 小 25~35%，AVIF 更小（压缩 40~60）。照片一律 WebP，简单图形用 SVG。
- 首屏图片：preload + 不懒加载（它是 LCP——最大内容绘制，决定" perceived 速度"）。
- 首屏以下：全部 `loading="lazy"`。
- 按显示尺寸出图：展示 800px 就别传 4000px 原图。

**落点**：
- 潘熠网站实战：9 只吉祥物 PNG→WebP，首屏从 ~12MB 压到 748KB——这是真实吃过的教训换来的。
- 案例图多，下一步：检查每张案例图是否按显示尺寸出图，首屏以下是否全懒加载。

### 5.2 首屏速度

**原则**（Core Web Vitals）：
- LCP（最大内容绘制）≤ 2.5s——首屏最大那张图/那行字多久出来。
- INP（交互延迟）≤ 200ms——点了多久有反应。
- CLS（布局偏移）≤ 0.1——加载时页面别跳（图片没定宽高是最常见的跳）。

**落点**：
- CLS 教训：所有图片必须写死宽高比（或 aspect-ratio），否则图片一加载，下面的文字"跳"一下——用户会觉得网站"不稳"，不稳 = 不专业。
- 字体：`font-display: swap`，别让文字等字体到了才显示（又是白屏）。

### 5.3 "慢"是最贵的体验税

**原则**：每慢 1 秒，转化率掉约 7%（经典数据，多份研究互相印证量级）。但更重要的是：**慢摧毁的是"高级感"**——一个 5 秒才出来的深色高级网站，客户的第一印象不是"高级"，是"卡"。

**我的判断**：潘熠网站的"克制高级暗色"定位，对性能的要求比普通网站更高。高级感 = 一切恰到好处，卡顿是"不恰到好处"里最致命的一种。性能不是技术指标，是设计指标。

- ✅ 正例：748KB 首屏，秒开，深色 + 香槟金一出来就是"贵"。
- ❌ 反例：12MB 首屏，转圈 5 秒——客户在看到"高级"之前，先看到了"不行"。
- **动手检查**：Chrome DevTools → Lighthouse，每次大改后跑一遍，LCP/CLS 变红就修。

## 六、一句话总结

> **网页设计 = 平面设计的规矩 + 时间维度的克制 + 性能维度的诚实。**
> 排版布局用平面那套（CRAP、网格、对比），动效只做标点不做正文，性能是高级感的地基。
> 潘熠网站的三色系统（深灰底+米白字+低饱和金）天然符合深色规范——审美直觉和工程规范在这里是同一件事。
